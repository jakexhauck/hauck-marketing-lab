# CAPI & Tracking Best Practices

## TL;DR
CAPI is mandatory post-iOS14. Target 80%+ match rate. Deduplicate with event_id. No tracking = no optimization.

## Why CAPI is Mandatory

```
iOS14+ Impact:
- ~40% of conversions lost with pixel-only
- Attribution windows shortened
- Data quality degraded

CAPI Solution:
- Server-side tracking
- Bypasses browser restrictions
- Better match rates
```

## Event Hierarchy

```
PageView (all pages)
    ↓
ViewContent (product/sales)
    ↓
AddToCart (intent)
    ↓
InitiateCheckout (high intent)
    ↓
Purchase (conversion)
```

## CAPI Requirements

### Mandatory Parameters
- event_name
- event_time
- action_source = "website"
- event_source_url
- user_data (at least one identifier)

### User Data Priority
| Priority | Parameter | Impact |
|----------|-----------|--------|
| Required | client_ip_address | Base matching |
| Required | client_user_agent | Device matching |
| Required | fbp/fbc | Facebook IDs |
| High | em (email, hashed) | Best match rate |
| High | ph (phone, hashed) | Strong match |
| Medium | fn, ln (names) | Additional matching |

## Match Rate (EMQ) Targets

| Score | Status | Action |
|-------|--------|--------|
| 9-10 | Excellent | Maintain |
| 7-8 | Good | Minor improvements |
| 5-6 | Acceptable | Add parameters |
| 3-4 | Poor | Priority fix |
| 1-2 | Critical | Stop spending |

## Deduplication (Critical)

```
RULE: event_id MUST match between pixel and CAPI

Same event_id = Deduplicated correctly
Different event_id = Counted twice (BAD)
Missing event_id = No deduplication
```

## Pre-Launch Checklist

```
□ Pixel ID correct on all pages
□ CAPI access token valid
□ Test events received
□ Deduplication working
□ Match rate > 60%
□ Event parameters complete
□ Values accurate
```
